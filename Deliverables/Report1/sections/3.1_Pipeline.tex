In our package the supported macro-architectures are Direct (Encoder + FFn) and Autoencoder (AE + FFn).
The encoder may be RNN/LSTM/GRU, Conv1D (temporal convolutions with pooling), or MultiScaleCNN (parallel convolutional branches at multiple receptive fields). If enabled, the decoder mirrors the encoder. Finally a feed-forward head performs classification.


We firstly considered a direct architecture as a baseline presented during the course, and then we have added the possibity to use the AE to increase the stability of the embeddings thanks to the reconstruction loss. In addition, the AE allows us to include the unlabeled test data to help decreasing the reconstruction loss while keeping untouched the prediction loss. We chose to do that since, as stated in \autoref{sec:problem}, the train data are few compared to the test data.  


\noindent \textbf{3.3 Pipeline}

\noindent Once the dataset is preprocessed, we setup the Optuna study, connecting all the computational resources available (e.g. local, Kaggle and Colab GPUs) to the same experiment in the Database.
The optimization routine executes $n_{\mathrm{trials}}$. For each trial, Optuna samples an architecture/hyperparameter configuration among the implemented ones, using the \href{https://optuna.readthedocs.io/en/stable/reference/samplers/generated/optuna.samplers.TPESampler.html}{TPE sampler} and \href{https://optuna.readthedocs.io/en/stable/reference/generated/optuna.pruners.MedianPruner.html}{Median Pruner}.
This allows to reach faster a good configuration compared to the standard grid search or MC sampling.
