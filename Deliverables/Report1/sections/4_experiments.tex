\section{Experiments}

This section details the experimental setup adopted to evaluate candidate models. We present the training protocol, cross-validation strategy, and performance metrics, and explain how hyperparameter optimization is conducted. The reported experiments serve as the empirical foundation for assessing the effectiveness of the proposed architectures and preprocessing techniques.

\subsection{Experimental Setup}

All experiments were conducted using the \texttt{FinalPipeline} framework, which integrates preprocessing, model construction, K-fold cross-validation, and Optuna-based hyperparameter optimization into a unified workflow. Unless otherwise specified, each configuration was evaluated under $K=5$ stratified folds to obtain robust and low-variance performance estimates.  

\subsubsection{Training Protocol}

For every trial generated by the Optuna study, the following steps were executed:
\begin{enumerate}
    \item Construction of the encoder (LSTM/GRU, Conv1D, or MultiScaleCNN) and, when applicable, a decoder for autoencoder-based models.
    \item Application of He initialization to convolutional and linear layers.
    \item Training over all $K$ folds using PyTorch Lightning with
    \item Model-level windowing and Aggregation of predictions, when enabled.
\end{enumerate}

\subsubsection{Evaluation Metrics}

Performance is assessed using the macro-averaged F1-score:
\[
    \mathrm{F1}_{\text{macro}} = \frac{1}{3}\sum_{c=0}^{2} \mathrm{F1}_{c},
\]
where $\mathrm{F1}_{c}$ denotes the class-specific F1-score computed for class $c \in \{0,1,2\}$.  
This metric is particularly suitable for class-imbalanced multiclass problems such as pain-level prediction.

Additionally, during development we monitor:
\begin{itemize}
    \item validation loss,
    \item per-class precision and recall,
    \item training/validation time per fold,
    \item number of parameters and computational cost of each model.
\end{itemize}
